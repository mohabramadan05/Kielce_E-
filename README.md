# Kielce_E — Developer Guide

The Erasmus+ website for **Kielce University of Technology (KUT)**. Built with Next.js (App Router) and available in **English and Polish**, with **light and dark themes**.

This guide explains how the project is put together, so you can add pages and content without breaking the shared parts.

---

## 1. Tech stack

| Area | Tool | Notes |
|---|---|---|
| Framework | **Next.js 16.4** (App Router, Turbopack) | Some APIs differ from older Next.js versions; see the warning below |
| UI | **React 19.3**, TypeScript (strict) | |
| Styling | **Tailwind CSS v4** | The theme is set in CSS (`globals.css`), not in a JS config |
| i18n | **next-intl v4** | Locales: `en` (default), `pl` |
| Theming | **next-themes** | Light / dark / system, set through `data-theme` on `<html>` |
| Icons | **lucide-react** | |

> ⚠️ **Next.js 16 is not the Next.js you may know.** `AGENTS.md` (auto-generated by `next dev`) warns that APIs and conventions have changed. One example in this repo: middleware now lives in **`proxy.ts`**, not `middleware.ts`. If you're unsure about an API, check `node_modules/next/dist/docs/`.

### Running it

```bash
npm install
npm run dev      # http://localhost:3000  → redirects to /en
npm run build    # production build
npm run lint
```

No environment variables are needed right now.

## 2. Folder structure

```
kielce_e/
├── app/
│   └── [locale]/                 ← every route sits under the locale segment
│       ├── layout.tsx            ← root layout: <html>, fonts, providers, Header/Footer
│       ├── page.tsx              ← Home page  (/en, /pl)
│       ├── globals.css           ← Tailwind import + design tokens (colours, themes)
│       └── students/
│           └── coordinators/
│               └── page.tsx      ← /en/students/coordinators
├── components/
│   ├── layout/                   ← site-wide parts: Header, Footer, NavLinks, switchers
│   ├── providers/                ← ThemeProvider (wraps next-themes)
│   └── ui/                       ← page sections, grouped by page
│       ├── home/                 ← hero, why, testimonials, get, contact
│       └── students/coordinators/← hero, coordinators, admin, dept
├── config/site.ts                ← site name + navigation menu structure
├── i18n/                         ← next-intl setup (routing, request, navigation)
├── messages/                     ← translation files: en.json, pl.json
├── hooks/useMounted.ts           ← "is this running on the client?" helper
├── types/nav.ts                  ← nav item types + isGroup() type guard
├── assets/                       ← images imported in code (logos, hero photos)
├── public/                       ← static files served as-is (mostly Next.js defaults)
├── proxy.ts                      ← locale middleware (redirects / → /en, etc.)
└── next.config.ts                ← next-intl plugin + experimental flags
```

**Rule of thumb:** `app/` holds only thin route files. Each page is a list of section components from `components/ui/<page>/`.

## 3. How a request is handled

```
Browser → proxy.ts (next-intl middleware)
            │  picks the locale, redirects "/" → "/en"
            ▼
       app/[locale]/layout.tsx
            │  checks the locale (404 if unknown), loads messages,
            │  wraps everything in NextIntlClientProvider + ThemeProvider,
            │  renders <Header/> … <main>{page}</main> … <ThemeSwitcher/> <Footer/>
            ▼
       app/[locale]/<route>/page.tsx
            │  builds the page from section components
            ▼
       components/ui/<page>/*.tsx (async Server Components using getTranslations)
```

- `proxy.ts` skips `api`, `_next`, `_vercel` and any path with a file extension.
- `layout.tsx` uses `generateStaticParams()`, so both locales are pre-rendered at build time.
- `layout.tsx` also builds `<title>` and the meta description from the `Metadata` namespace in the messages.

## 4. Internationalisation (EN / PL)

### Files
| File | Purpose |
|---|---|
| `i18n/routing.ts` | Lists the locales (`en`, `pl`) and the default (`en`). **Change locales only here.** |
| `i18n/request.ts` | Loads `messages/<locale>.json` for each request. |
| `i18n/navigation.ts` | Locale-aware `Link`, `useRouter`, `usePathname`, `redirect`. |
| `messages/en.json`, `messages/pl.json` | The translations, grouped by namespace. |

### Namespaces in use
`Metadata`, `Header`, `Footer`, `HomePage`, `Theme`, `Coordinators`.

### Using translations

**Server component** (the default for sections):
```tsx
import { getTranslations } from "next-intl/server";

export default async function MySection() {
  const t = await getTranslations("HomePage");
  return <h1>{t("why")}</h1>;
}
```

**Client component** (`"use client"`):
```tsx
import { useTranslations } from "next-intl";
const t = useTranslations("Theme");
```

### Rules
1. **Any text a user sees goes in the messages files.** Add every key to **both** `en.json` and `pl.json` with the same name.
2. **For internal links, use `Link` from `@/i18n/navigation`, not from `next/link`.** The i18n `Link` keeps the current locale (`/pl/...`). A `next/link` to `/students/incoming` drops the prefix and relies on a middleware redirect.
3. **Every page must call `setRequestLocale(locale)`** before using translations. Otherwise next-intl falls back to reading `headers()`, and with `cacheComponents` on, Next.js 16 fails with a *"Blocking Route … encountered runtime data during prerendering"* error.

`LanguageSwitcher` stays on the same page and only swaps the locale: `router.replace(pathname, { locale })`.

## 5. Theming and styling

### Design tokens (`app/[locale]/globals.css`)
Colours are CSS variables set twice, once for light (`:root`) and once for dark (`:root[data-theme="dark"]`). `@theme inline` turns them into Tailwind utilities:

| Token | Tailwind classes | Use |
|---|---|---|
| `--bg` | `bg-bg` | Page background |
| `--surface`, `--surface-2` | `bg-surface`, `bg-surface-2` | Cards, alternate sections |
| `--text` … `--text-4` | `text-fg`, `text-fg-2`, `text-fg-3`, `text-fg-4` | Text, from strongest to faintest |
| `--line`, `--line-2` | `border-line`, `border-line-2` | Borders and dividers |
| `--brand` | `bg-brand`, `text-brand` | KUT navy (#11406e) |
| `--brand-ink`, `--brand-ink-hover` | `text-brand-ink`, `hover:text-brand-ink-hover` | Brand-coloured text and links (readable in both themes) |
| `--brand-tint` | `bg-brand-tint` | Soft brand background (badges, icon tiles) |

**Use these token classes instead of raw colours** (`#1e3a5f`, `text-slate-900`, `bg-gray-…`). Raw colours don't switch with dark mode. The only deliberate exception is the faculty accent colours on the Coordinators page (see §7).

### Theme switching
- `components/providers/ThemeProvider.tsx` configures next-themes: `attribute="data-theme"`, default `system`.
- `components/layout/ThemeSwitcher.tsx` is the floating button in the bottom-right corner. It uses `useMounted()` so it doesn't render until the client knows the real theme, which avoids a hydration mismatch.

> `tailwind.config.js` is **not used** by Tailwind v4 here. It points to variables that don't exist (`--app-color-primary`). Add new tokens in `globals.css` instead.

## 6. Navigation and layout

### Menu config: `config/site.ts`
The header menu is set up in one place:

```ts
nav: [
  { key: "about", children: [ { key: "policy", href: "/about/policy" }, ... ] }, // dropdown
  { key: "ka220", href: "/ka220" },                                               // plain link
]
```

- `key` is a translation key in the **`Header`** namespace. Add it to both message files.
- `href` has **no locale prefix**; the i18n `Link` adds it.
- An item with `children` becomes a dropdown.

### Components
| Component | Type | What it does |
|---|---|---|
| `Header.tsx` | Server | Turns `siteConfig.nav` into translated `NavItem[]` and renders the logo, `NavLinks`, `LanguageSwitcher` and the "Apply Now" button |
| `NavLinks.tsx` | Client | Desktop menu + mobile hamburger; dropdowns close on outside click or Esc; highlights the active route |
| `LanguageSwitcher.tsx` | Client | EN / PL toggle |
| `ThemeSwitcher.tsx` | Client | Light / dark toggle |
| `Footer.tsx` | Server | Contact block, explore links, social links |

`types/nav.ts` defines `NavLinkItem`, `NavGroupItem` and the `isGroup()` guard used by `NavLinks`.

| File | Section |
|---|---|

## 8. Adding a new page (checklist)

Example: `/students/incoming`

1. Create `app/[locale]/students/incoming/page.tsx`:
   ```tsx
   import { setRequestLocale } from "next-intl/server";
   import Hero from "@/components/ui/students/incoming/hero";

   export default async function IncomingPage({
     params,
   }: { params: Promise<{ locale: string }> }) {
     const { locale } = await params;
     setRequestLocale(locale);
     return (
       <div className="flex flex-col flex-1 items-center bg-bg">
         <Hero />
       </div>
     );
   }
   ```
2. Put its sections in `components/ui/students/incoming/` as async Server Components using `getTranslations("Incoming")`.
3. Add an `"Incoming"` namespace to **both** `messages/en.json` and `messages/pl.json`.
4. If it needs a menu entry, add it to `config/site.ts` and add its label to the `Header` namespace.
5. Use the token classes (§5), the `@/` import alias, and `Link` from `@/i18n/navigation`.
6. Check it in **both languages** and **both themes** before opening a PR.

Only add `"use client"` to a component when it needs state, effects or browser APIs. Keep it as small as possible, like `NavLinks` and `ThemeSwitcher`.

## 9. Conventions

- **Imports:** prefer the `@/` alias (`@/components/...`) over long relative paths like `../../../../`.
- **Components:** sections use default exports. Layout parts use named exports (`export function Header`).
- **File names:** layout components are PascalCase (`Header.tsx`); page sections are lowercase (`hero.tsx`). Keep to whichever style the folder already uses.
- **Images:** import from `assets/` (`import logo from "@/assets/logo-uni.png"`) so `next/image` knows their size.
- **Text:** no hard-coded UI strings. Everything goes through the messages files.
